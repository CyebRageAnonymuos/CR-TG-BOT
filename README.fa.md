## 🚀 دیپلوی روی Railway

```bash
# 1. ساخت توکن ربات
#    @BotFather  →  /newbot  →  توکن رو کپی کن

# 2. گرفتن آیدی عددی خودت
#    @userinfobot  →  این آیدی ADMIN_IDS شماست

# 3. آپلود این پوشه در گیت‌هاب و اتصال در Railway:
#    New Project → Deploy from GitHub repo
#    Railway خودش Dockerfile رو تشخیص می‌ده.
```

سپس این متغیرها را در **Variables** پروژه تنظیم کنید:

| کلید | مقدار |
|---|---|
| `BOT_TOKEN` | توکن گرفته‌شده از BotFather |
| `ADMIN_IDS` | آیدی عددی ادمین(ها) - با کاما جدا کنید |
| `CARD_NUMBER` | شماره کارت نمایش داده‌شده به خریدار |
| `CARD_HOLDER` | نام صاحب کارت |
| `DB_PATH` | `/data/bot.db` (مرحله Volume را ببینید) |
| `BRAND_NAME` | نام برند در پیام خوش‌آمدگویی (پیش‌فرض `CR`) |
| `SUPPORT_USERNAME` | آیدی پشتیبانی بدون @ (پیش‌فرض `CYBRSupport`) |
| `REFERRAL_REQUIRED_COUNT` | تعداد خرید موفق لازم برای فعال شدن هدیه رفرال (پیش‌فرض `3`) |

### 💾 ماندگاری دیتابیس (مهم)

> فایل‌سیستم Railway در هر دیپلوی ری‌ست می‌شود. برای حفظ سفارش‌ها:

1. در تب **Volumes** یک Volume ساخته و در مسیر `/data` مانت کنید
2. مقدار `DB_PATH=/data/bot.db` را حفظ کنید

ربات حالا **ضد کرش** است: در زمان راه‌اندازی خودش مسیر دیتابیس را می‌سازد و خطای معروف `unable to open database file` دیگر هرگز رخ نمی‌دهد.

## 🛒 مسیر خرید

`خرید سرویس` → انتخاب تعرفه → خلاصه سفارش + شماره کارت با دکمه‌های:
**📤 ارسال رسید** · **💰 پرداخت با کیف پول** (اگر موجودی کافی باشد) · **🔙 بازگشت**

سفارش با دکمه‌های **✅ تأیید / ❌ رد** برای ادمین ارسال می‌شود. بعد از تأیید، ادمین اطلاعات پنل/کانفیگ را می‌فرستد و ربات **به‌صورت خودکار** به خریدار تحویل می‌دهد.

## 🛠️ پنل مدیریت ربات (`/admin` یا دکمه منو)

- **تعرفه‌ها** — تغییر قیمت، فعال/غیرفعال کردن، افزودن پلن جدید
- **✉️ پیام خوش‌آمدگویی** — کاملاً قابل تغییر (HTML)
- **📜 قوانین** — متن دلخواه
- **🤝 تنظیمات رفرال** — درصد پورسانت نقدی به ازای هر خرید موفق زیرمجموعه
- **🎟️ کدهای تخفیف** — ساخت/فعال‌سازی/غیرفعال‌سازی/حذف
- **💳 تخفیف شارژ کیف پول** — آستانه و درصد هدیه پلکانی

همه تنظیمات در SQLite ذخیره می‌شوند و با ری‌استارت از بین نمی‌روند (به شرط نصب Volume).

## ⚡ عملکرد

- SQLite با حالت **WAL** (`journal_mode=WAL`، `busy_timeout=10s`، `synchronous=NORMAL`) — خواندن هم‌زمان هیچ‌وقت قفل نمی‌شود، دیگر خبری از کرش قفل دیتابیس نیست
- **ساخت خودکار مسیر دیتابیس** — بدون هیچ تنظیم Volume هم روی هر هاست دیپلوی می‌شود
- محافظت در برابر اسپم روی همه پیام‌ها و دکمه‌ها

## 🗂️ ساختار فایل‌ها

```
├── bot.py           # فایل اصلی ربات + همه هندلرها + پنل ادمین
├── config.py        # متغیرهای محیطی، مقادیر پیش‌فرض، تعرفه‌های اولیه
├── database.py      # لایه SQLite (WAL، ساخت خودکار مسیر، ۵۰+ کوئری)
├── requirements.txt
├── Dockerfile
├── railway.json
├── env.example
└── .gitignore
```
